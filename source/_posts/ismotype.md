IsmoType 的第一版有 500 道题、44 个维度，全部塞在一个手写的 data.js 里。决定重建之前，先对旧版跑了一次只读审计，结论里的两行数字说明了问题：500 道题里有 296 道既不加载 MBTI 权重、也不加载任何标签，对任何得分都贡献 0；其中一个文件的 100 道题全部惰性。另一个数字更直接：选 100 题作答时，E/I 维度的可得分恒为 0，而旧代码 `score >= 0 ? 'E' : 'I'` 会把所有人判成 E，首字母对每个人恒定不变。

两个数字指向同一处结构问题：旧题库把 44 个维度写成一个位置数组，题目和维度各自独立，整条链路里没有任何一步检查「某个维度到底有没有题在测它」。所以这次的处理是整体推倒重做，没有在旧结构上修补。现在的 IsmoType 是 358 道题、12 个构念、37 个维度、121 个主义，计分引擎是纯 TypeScript，不依赖任何框架；界面是 Vue 3.5 + Vite 8 + Pinia + vue-i18n，纯静态、没有后端，作答只存浏览器本地。

下面按决策顺序记录三组内容：维度数怎么从 44 变成 37，哪几处算法差一点把结果判反，以及为什么有些数字宁可空着也不编一个出来。

## 维度数由四道闸门决定

旧版 44 个维度跑主成分分析的结果：名义上 44 维，独立信息量大约 7 维（Kaiser 准则），有 26 对维度相关系数绝对值不低于 0.80，其中「社会秩序 ↔ 法律权威」达到 0.965。26 对聚成 7 簇，盖住 40 个维度，本质上是同一批题在换词重问。

重建时维度数不预设。先人工重写 121 个主义的全部轮廓，再跑一道有效秩剪枝。每个维度都要写清三样：definition（测什么）、excludes（不测什么，必须点名最容易混淆的相邻维度）、anchors（高低锚点例句），缺一项闸门直接报失败。之后叠四道硬闸门：

- 覆盖度：每个维度至少 12 道题加载它。
- 近重复：两道题换措辞后相似度过高即拦截，阈值 0.55，按本库中英两语的空白带实测定。
- 冗余对：任意两个维度的 |r| 超过 0.9 即出局。
- 唯一方差：某维度 1−R² 低于 0.15，说明它基本是别的维度的线性组合，出局。

四道闸门跑在「LLM 起草、人工修改」的题库载荷上，黄金锚集用来检测标注漂移，偏离阈值就停下重校。近重复闸门在建成后的下一批就抓到第一对目标：一对相似度 1.000、一对 0.650，都是实质相同、只换了措辞。机器只挡得住字面重复：「治理是专业活，交给有见识的人」和「让最懂行的人来定」这种同义题，中文相似度只有 0.063，只能靠人读出来。

## 唯一方差的 0.15 与主导因子口径

唯一方差的阈值最初定在 0.20。四轮人工撰写、58 处调整之后还剩 7 个维度卡在 0.169–0.200，继续改出现「跷跷板」：修好一个，另一个就掉下去。这个现象指向意识形态数据自身的一条贯通左—右轴，继续加题不会让它消失。降到 0.15 后闸门全绿：冗余对从 4 对归零，首成分平均共同度从 29.2% 降到 15.8%。

还有一个更早的取舍。121 个主义的轮廓如果直接从旧 44 标签线性投影到新 37 维，会继承旧词表的秩亏：投影的秩不超过原矩阵的秩，实测 Kaiser 只有 7、29 个维度唯一方差低于 0.20。另一条路是把分类学缩到 7–10 维。最终选了人工重写全部 121×37 个轮廓，投影表只留作交叉校验。

主导因子闸门的阈值改过三轮。最初写「任一特征值 > 3.0」，跑下来发现这个绝对值随维度数漂移：3.0 在 4 维时相当于 75%，在 37 维时只相当于 8%。改成「最大特征值 ÷ 维度数」又被推翻：3 个两两不相关的维度会算出 33%，被误判成压倒性单轴。最终落到 `(λ₁ − 1)/(p − 1)`：两两独立时为 0，完全同向时为 1，与维度数无关。

## 余弦匹配与白化

匹配用余弦相似度：作答先按题目载荷投影到 37 维向量，和每个主义在同一组维度上的轮廓算点积，两边都做 L2 归一化，落成 0–100 的匹配度。

更高阶的算法也试过。恢复率测试的做法是：取某个主义的向量当用户真实轮廓，叠上噪声，看引擎能不能把它排回第一。噪声 1.0× 标签标准差时，原始余弦夺冠率 89.4%，中心化后 87.7%，白化（马氏距离）只有 59.2%。零噪声时四种方法全是 100%：主义向量本身可以完全区分，失败全来自测量噪声，改进重心在题面质量。

## 置信度的两档阈值

top1 和 top2 有多接近，用一个判定量描述：冠军比亚军高出多少个构念内标准差。阈值有出处：把判定量分桶后看每桶的恢复率，恢复率跃升最大的两处落在 0.067 和 0.717，就定成 low / high 的界（0.07 和 0.72）。

这两个阈值只在「单构念判定量」这一口径上成立。K 个构念取最小是一个随 K 单调收缩的统计量，套到跨构念最小值上，high 会永不可达。跨构念最小值这条口径不能直接决定全局档位，全局档位由各构念档位的分布决定。

这一套引擎照常计算，但界面上不展示三档文字：12 张卡里挂 7 张「与 X 非常接近」的红字，既长得一样又看不出差别，比数字更吵。页面上的事实交给贴合度百分比承担。

## 六点、五点、七点

358 道题分三段，点数不一样：立场 248 题六点、性格底色 50 题五点、风格类型 60 题七点。三段点数都不能改，各有各的外部锚：

- 立场六点是自订的，权重 `[2.5, 1.5, 0.5, -0.5, -1.5, -2.5]`，同意在前。
- 性格底色用 IPIP-50 原题，五点是它公开发布时的格式，改了就查不了常模。
- 风格类型七点沿用源站的百分比口径 `Math.ceil(score / 2) + 50`，改点数这条公式就废了。

## 打平就多问一道，权重 1.5

某维恰好打平（raw = 0）时，界面不显示中间态 X，改出一道二选一定向题。定向题的权重取 1.5，这个数有出处：源站的 `Math.ceil(score / 2) + 50` 在 raw = ±1.5、满分 37.5 时两个方向都得 52%，取 1 会得到 52% / 51% 的不对称，等于让「选左边」比「选右边」多显示一个百分点。

中间态 X 在核心层是故意保留的：每题都能选中立，把 0 悄悄默认到某一极，正是旧项目 E-lock 的同型复发。

## 整层判分方向反了，三道闸门全照过

风格类型层最早把七点写成 `option - 3`，让索引 0（「非常同意」）落到 −3。于是「你经常结交新朋友」选「非常同意」，会把人判成内向，整层方向反了。立场层也翻过：权重 `OPTION_WEIGHTS[0]` 是 +2.5（最同意），界面标签却写「不同意」在前。

结构、覆盖度、均衡三道闸门全部照过。因为这类错的形态正是「数组位置自洽、和渲染出来的字相反」：机器看代码是对的，人看页面是反的。抓它的测试不能写死数字，得从标签取值：测试读「同意在前还是不同意在前」，再和权重表索引 0 的符号比对。现在两个「同意」量表（主义六点、风格七点）都同意在前、索引 0 为正；IPIP 是「准确」量表，索引 0 最不准确、取值 1。

IPIP 还踩过一个对称的坑：一度把五点写成 `[2, 1, 0, -1, -2]`，等于从另一头数，原始分落在 [−20, 20]，偏离了可查常模需要的 10–50 区间，任何常模表都得先做一次仿射换算才用得上。改回 1–5 之后 raw 才回到 10–50。

## 16personalities 的判读

风格类型那段的题库与框架来自 16personalities（NERIS Type Explorer），与 Myers & Briggs Foundation 的官方 MBTI 没有隶属关系。MBTI 是 Myers & Briggs Foundation 的商标，这里只做描述性指称，界面沿用「MBTI」这个中文口语叫法，真实来源写进仓库文档。它也不分配荣格认知功能。

更实在的问题在「判读」：源站题库里没有任何维度字段，每题属于哪一维、同意推向哪一极，计分只在服务端，公开页面拿不到。60 题按「每维正好 12 题」去配平判读，其中一条 `mq_53`（「觉得对就直接行动，不需要更多证据」）字面两读都通，只有归到 Nature 才配得平。

为排除原判读者的先入为主，另找了一个不知道答案的人从零重判一张盲表。60 题里 59 题完全一致，唯一分歧是一道「更关注受影响者的感受」的题，一方判 Mind、一方判 Nature。最终按三条理由裁到 Nature：它是源站另外两题的镜像、判读者自己把它列为最没把握的一条、改判之后五维恰好 12/12/12/12/12 配平。配平是独立于判读的算术约束，错一条就打破它。

## 没有常模，百分位留空

性格底色的百分位，中文常模在公开网络上拿不到可核实的学术来源：检索全程被同名的 IP 库站点淹没。所以常模表以空表落地，`percentile` 全程为 null，界面显示「暂无可比常模」，不编一个看起来像百分位的数字。接入常模只需填一个 JSON，代码不用动。

显示层还有一个坑：大五偏差条一度是线性的，随机作答时五条都落在中间，看起来像「坏了」。实际是随机作答本就不含信息，线性条长让「落在中间」只有满格 1/4 宽。改成长度 ∝ √|偏差| 之后差异读得出来，且只动显示不动原始分。

## 手写的雷达图与分享图

结果页的雷达图是手写内联 SVG，分享图是 Canvas 画的 1080×1920 长图，没有引图表库也没有引 Canvas 库。

雷达图第一版把主义名写在 SVG `<text>` 里，结果字号跟着渲染尺寸缩放：中英文名长短不同 → 视框宽窄不同 → 同一份代码中文渲出 13px、英文 9.7px，连图的大小都跟着语言变。现在标签是 HTML，绝对定位在 SVG 外面，字号由 CSS 定死。分享图跟随当前主题，暗色图发到白底信息流里是一块黑，所以亮暗两套各要生成一次对照。

Canvas 侧为了能测，把「画什么、画在哪、多宽多高」算成一个纯函数产出的指令列表，真正调 canvas API 的那层薄到只剩照着执行。测试环境 happy-dom 没有 canvas，但指令列表是纯数据，两条不变量（任何指令不越出画布、任意两段文字不重叠）都能在测试里守住。后者当场抓到过一处真重叠：领域名和主义名只差 28px，两行字加起来 40px 高。

## 0.1.2 依赖升级

0.1.2 没有任何功能变化，就是依赖审计报了三个包的安全漏洞：vite 从 8.3.1 升到 8.3.3、vue-i18n 从 11.4.12 升到 11.4.14，以及 vite 传递引入的 source-map-js 从 1.2.1 升到 1.2.4。版本号有两处真相源：`package.json` 和 `src/core` 里的 `CORE_VERSION`，页脚显示的就是后者，两处漂移是看得见的错，这次一并从 0.1.1 提到 0.1.2。

## 限制

- 风格类型层无法按「有真实数据」的标准验证：题库与框架来自 16personalities，每题归属是判读出来的，「每维 12 题」是配平约束下的自洽解，没有从源站查证到的事实支撑。
- 没有常模，就没有百分位，只有原始分和定性区间。
- 358 道题的完成率还没验证：进度可以存本地、中途可停，但没做过「答一半刷新再继续」的完整人工走查。
- 近重复闸门只挡字面重复，语义重复只能靠人读，机器相似度对这种同义题基本是瞎的。
