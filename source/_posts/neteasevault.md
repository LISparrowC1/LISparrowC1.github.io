「我喜欢的音乐」看着像收藏，其实只是一份随时会失效的播放权限：版权到期、单曲下架、账号异常、客户端改版，任何一样都能让几百首歌突然点不开。NeteaseVault 把这份歌单同步到本地，逐首下载、校验、清洗，目标是十年后这些文件还能直接播放，而且没有一首是错的歌。

这篇写它怎么做到这一点，也写清楚哪些地方它明确做不到。

## 为什么是归档，不是下载器

下载器解决「现在想听」：搜到、下完、能播，任务就结束了。归档要解决「十年后还想听」，所以除了下载，还得回答三个问题：

- 下到的是不是**同一首歌**？翻唱、Live、伴奏、同名不同版本，都是真实存在的坑。
- 文件是不是真的**无损**？320K 转码改个后缀就是 FLAC，播放器看不出来。
- 云端状态变了，**本地记录还认不认得**？今天取消喜欢、明天加回来，下载状态不能丢。

整个项目就是围绕这三件事搭起来的。

## 先认身份，再比元数据

候选来自三条通道，按设置里的顺序依次尝试：`musicdl` 搜索、洛雪（LX Music）生态的自定义源脚本、官方接口。

- 官方接口和自定义源拿到的本来就是**同一个网易 `song_id`**，属于同一首歌，不需要猜。
- `musicdl` 是搜索来的，要过四道规则：歌名、歌手、专辑归一化后完全相等，时长按整秒相等。
- 归一化只动四处：全角转半角、合并空白、大小写、繁简中文，外加清掉零宽字符。**不剥** `feat.`、`Live`、`Remix`，也不做模糊包含——那会改变含义。
- 四道规则全过还不够，还必须**唯一**：两个候选都合规，同样转人工。

转人工不是失败。待确认列表会把每个候选的来源、标题、歌手、专辑、时长、音质、大小，以及没通过哪条规则一起列出来；可以试听，也可以指定其中一条入库。自动流程只接受无损，320K 这类必须人工点头才进得了库。

## 验真：不信后缀

判断一个文件是不是真无损，分三层：

1. **容器嗅探**：只读文件头，不认扩展名。声明是无损、实际却是 MP3 帧的，直接判假。
2. **码率下限**：无损容器的平均码率低于 400 kbps，基本可以确定是转码后重新封装的。
3. **高频落差**：真无损的高频会自然衰减，转码文件在 20 kHz 以上往往是空的。判据取 18–20 kHz 与 20–22 kHz 两个频段的平均能量差。

| 落差 | 结果 |
| --- | --- |
| 大于 -30 dB | 通过 |
| -30 至 -40 dB | 灰区，记录后放行 |
| 小于 -40 dB | 判为转码，丢弃 |

频谱只当辅助判据：只拦明确判假的文件，灰区放行但写进日志；采样率不高于 44.1 kHz 时无法可靠判定，宁可记为「未知」，也不硬判通过。真正硬性的两道闸门是容器和码率。

## 三条轴，七个列表

用一个 `state` 字段同时表示「在不在歌单」和「下没下载」，是这类工具最容易犯的错。NeteaseVault 把它拆成互不覆盖的几条轴：

- `cloud_present` / `cloud_playable`：云端现在有没有、能不能播
- `local_state`：本地是 `none`、`downloaded`、`pending_review` 还是 `match_failed`
- `local_only`：磁盘上有文件，但云端没有对应记录

同步只更新云端字段，**不会覆盖 `local_state`**。取消喜欢再加回来，下载状态照样在。

七个列表因此不需要单独存「这首歌属于哪个列表」，全部由 SQL 谓词推导：

![三条轴推导出七个列表](/img/projects/neteasevault-views.webp)

两条配套规则：

- 本地文件和云端记录的关联**每次从磁盘重新推导**，不当作独立状态保存。数据库重建后重新同步，`music/` 里的文件还是能被认回来。
- 顶部统计只算云端歌单：一首歌离开歌单后，「已下载」的数字会跟着下降，而不是一直虚高。

## 一次下载经过什么

![下载流水线](/img/projects/neteasevault-flow.webp)

1. **同步**：按云端顺序读全部曲目，记录顺序、收藏时间、时长、云端音质上限、可播状态。
2. **找候选**：按通道顺序搜索或解析，收集候选。
3. **判定**：四道规则加唯一性。找不到合格候选的转「待确认」；在那里人工拒绝，才归入「匹配失败」。
4. **下载到暂存区**：写到 `data/staging/<song_id>/`，`.part` 分块写入，支持暂停、继续、取消；取消时临时目录一并删掉。
5. **探测**：按文件头识别容器，读出采样率、时长、码率，再做假无损判定。
6. **清洗**：剥掉文件头尾多余的标签：ID3v2 前缀、ID3v1 / APEv2 / Lyrics3；FLAC 只留 STREAMINFO 和标签块；标签只保留 `TITLE` / `ARTIST` / `ALBUM` / `LYRICS` 四项，歌词只留带时间戳的行。清洗完再解析一遍复核。
7. **入库**：文件名固定为 `歌名 - 歌手.flac`，非法字符替换掉，重名加序号，然后移进 `music/`。

失败的候选不会进 `music/`，暂存目录也会被清掉。

## 界面

- 七个列表：网易歌单、已取消喜欢、失效、等待下载、待确认、匹配失败、已下载。
- 每首歌的状态直接画在行里；下载时行尾显示百分比和一条细进度条。
- 双击已下载的歌开始播放。点播放栏的歌名进入整页播放界面：左边封面，右边歌词，当前行高亮并跟着滚动。
- 播放队列独立存在，可以随时打开、清空；清空会同时停止播放。
- 「刷新」重新扫描 `music/` 并核对数据库；「清空当前列表」只作用于定义这个列表的那一侧数据；「清除同步信息」保留本地文件，下次同步会自动重新关联。
- 设置里可以把 `music/` 镜像到 U 盘，并生成一份相对路径的 `我喜欢的音乐.m3u8`。

## 第一次用

1. 从 Release 下载单个 exe，放进任意目录，双击运行。
2. 点左上角账户卡 → 「重新登录」，粘贴 Cookie（获取方法见下一节）。
3. 点「同步」，把「我喜欢的音乐」读进本地。
4. 切到「等待下载」，点「下载」；不选歌就是下载整个列表。
5. 下载完的文件在 `music/` 里，双击列表行就能播放。

## 账户与构建

扫码登录已被网易关闭（服务端返回 8821），现在只有 Cookie：登录 music.163.com，F12 → Application → Cookies，复制 `MUSIC_U`。程序能解析整段请求头、分号列表和 JSON 三种粘贴形态，保存前会验证并显示昵称和 UID；凭证用 Windows DPAPI 加密，换个 Windows 账户读不出来。

从源码构建：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
pwsh -NoProfile -File build\build.ps1
```

产物是项目根目录下的单个 exe，约 150 MB。体积来自 Qt 运行时和内置的 Node（自定义源要用）。程序是可搬的：首次运行只在同级目录创建 `music/` 和 `data/`，数据库、凭证、日志、封面缓存、暂存区都在 `data/` 里，不写系统目录。

## 边界

- 只归档「我喜欢的音乐」一个歌单；不做云端上传，也不能编辑歌单。
- 不内置任何音源密钥或账号。自定义源脚本要自己准备、自己导入，脚本行为不由程序保证。
- 目前只提供 Windows 版。
- 网易的接口和风控随时可能变，同步或下载失效属于正常损耗，不是承诺。
