「我喜欢的音乐」看着像收藏，其实只是一份随时会失效的播放权限：版权到期、单曲下架、账号异常、客户端改版，任何一样都能让几百首歌突然点不开。NeteaseVault 把这份歌单同步到本地，逐首下载、校验、清洗，目标是十年后这些文件还能直接播放，而且没有一首是错的歌。

这篇写它怎么做到这一点，也写清楚哪些地方它明确做不到。

## 为什么是归档，不是下载器

下载器解决「现在想听」：搜到、下完、能播，任务就结束了。归档要解决「十年后还想听」，所以除了下载，还得回答三个问题：

- 下到的是不是**同一首歌**？翻唱、Live、伴奏、同名不同版本，都是真实存在的坑。
- 文件是不是真的**无损**？320K 转码改个后缀就是 FLAC，播放器看不出来。
- 云端状态变了，**本地记录还认不认得**？今天取消喜欢、明天加回来，下载状态不能丢。

整个项目就是围绕这三件事搭起来的。

## 先认身份，再比元数据

候选来自三条通道，按设置里的顺序依次尝试：`musicdl` 搜索、洛雪（LX Music）生态的自定义源脚本、官方接口。

- 官方接口和自定义源拿到的本来就是**同一个网易 `song_id`**，属于同一首歌，不需要猜。
- `musicdl` 是搜索来的，要过四道规则：歌名、歌手、专辑归一化后完全相等，时长按整秒相等。
- 归一化只动四处：全角转半角、合并空白、大小写、繁简中文，外加清掉零宽字符。**不剥** `feat.`、`Live`、`Remix`，也不做模糊包含——那会改变含义。
- 四道规则全过还不够，还必须**唯一**：两个候选都合规，同样转人工。

转人工不是失败。待确认列表会把每个候选的来源、标题、歌手、专辑、时长、音质、大小，以及没通过哪条规则一起列出来；可以试听，也可以指定其中一条入库。自动流程只接受无损，320K 这类必须人工点头才进得了库。

## 验真：解码之后再看

扩展名和码率都不够。文件落进暂存区后，程序会解码一段真实 PCM——取中段 60 秒，避开开头和结尾——做 FFT，拿三样东西：

- **频谱截止**：从 500 Hz 往上一段段算能量，找最后一个还在峰值 80 dB 以内的频段。
- **高频断崖**：在 14–22 kHz 之间，相邻 500 Hz 频段的最大落差。
- **平均码率**：用文件大小和时长算出来的实际码率。

然后按下表判定：

| 信号 | 结果 |
| --- | --- |
| 平均码率低于 400 kbps | 判假，丢弃 |
| 平均码率 400–600 kbps | 灰区，转人工 |
| 频谱截止低于 18 kHz | 判假，丢弃 |
| 频谱截止 18–20 kHz | 灰区，转人工 |
| 顶部八度出现 ≥ 40 dB 断崖 | 灰区，转人工 |
| 其余 | 通过 |

只有明确判假的会直接丢掉。灰区和无法判定都进「待确认」：不自动入库，也不直接扔，由人听过再决定；解码失败同样转人工，不会当作通过。人工接受非无损的 320K 文件时，不套用无损门槛。

还有一道与真伪无关的闸门：文件的**实际时长**要和云端时长按整秒相等，不一致就拒绝。这是发现「下错歌」最快的方法。

## 三条轴，七个列表

用一个 `state` 字段同时表示「在不在歌单」和「下没下载」，是这类工具最容易犯的错。NeteaseVault 把它拆成互不覆盖的几条轴：

- `cloud_present` / `cloud_playable`：云端现在有没有、能不能播
- `local_state`：本地是 `none`、`downloaded`、`pending_review` 还是 `match_failed`
- `local_only`：磁盘上有文件，但云端没有对应记录

同步只更新云端字段，**不会覆盖 `local_state`**。取消喜欢再加回来，下载状态照样在。

七个列表因此不需要单独存「这首歌属于哪个列表」，全部由 SQL 谓词推导：

![三条轴推导出七个列表](/img/projects/neteasevault-views.webp)

两条配套规则：

- 本地文件和云端记录的关联**每次从磁盘重新推导**，不当作独立状态保存。数据库重建后重新同步，`music/` 里的文件还是能被认回来。
- 顶部统计只算云端歌单：一首歌离开歌单后，「已下载」的数字会跟着下降，而不是一直虚高。

## 一次下载经过什么

![下载流水线](/img/projects/neteasevault-flow.webp)

1. **同步**：按云端顺序读全部曲目，记录顺序、收藏时间、时长、云端音质上限、可播状态。
2. **找候选**：严格按设置里的通道顺序搜索或解析。同一首歌在一个通道里可能拿到多个候选，一个地址失效会自动换下一个，全部失败才走下一通道。
3. **判定**：同一 `song_id` 直接认定；搜索候选要四项全等且唯一。不满足的候选会保留下来，最后一起进「待确认」。
4. **下载到暂存区**：写到 `data/staging/<song_id>/`，`.part` 分块写入，支持暂停、继续、取消；失败按设置重试，并发和搜索/下载限速都可调。
5. **校验**：容器嗅探、实际时长、PCM 频谱，三道都过才继续。
6. **清洗**：剥掉文件头尾多余的标签：ID3v2 前缀、ID3v1 / APEv2 / Lyrics3；FLAC 只留 STREAMINFO 和标签块；标签只保留 `TITLE` / `ARTIST` / `ALBUM` / `LYRICS` 四项，歌词只留带时间戳的行。清洗完再解析一遍复核。
7. **入库**：文件名固定为 `歌名 - 歌手.flac`，非法字符替换掉，重名加序号，然后移进 `music/`。

结果分三种：

- 所有通道都没有候选 → 「匹配失败」。
- 有候选，但都卡在灰区、时长、非无损或唯一性上 → 「待确认」。
- 通过全部校验 → 已下载，失败和取消都不会在 `music/` 里留下半成品。

## 自定义源：导入与排序

自定义源走 LX 的 `globalThis.lx` 协议：脚本只负责把歌曲 ID 换成播放地址。三条路都能用：

- **手动导入**：选任意 `.js`，复制到 `data/engine/scripts`；能不能加载由引擎在列表里报告，不再检查脚本格式。
- **自动获取**：从 `data/source_repos.json` 里配置的公开仓库发现脚本，校验 `@name`、`sources`、`lx` 初始化这些特征，写进临时目录，再用云端歌单里第一首未下载的歌逐个 `resolve`；只有真的解析出地址的脚本才会装成 `auto-*.js`。
- **健康检查**：用同一首云端样本测所有已安装源，失败会写明原因。

排好顺序很重要，因为下载就是按顺序试：

- 「上移 / 下移」手动排，立即生效；
- 「按测试结果排序」按成功优先、延迟升序、失败最后自动重排；
- 勾选「检查后自动排序」，健康检查结束就自动重排。

下载时某个源解析或下载失败会自动尝试同通道的下一个源；所有自定义源都失败，才继续下一个下载通道。通道顺序本身严格按设置执行，自定义源不会被强制排到最前面。

## 界面

- 七个列表：网易歌单、已取消喜欢、失效、等待下载、待确认、匹配失败、已下载。
- 每首歌的状态直接画在行里；下载时行尾显示百分比和一条细进度条。
- 双击已下载的歌开始播放。播放页左栏是封面、标题和歌手/专辑，下面有「歌词 / 频谱」切换；右栏显示歌词或整首静态频谱，当前歌词行会高亮并跟着滚动。
- 切到「频谱」后，左栏下方出现 300×55 的实时频谱：以水平中轴上下镜像，柱子紧贴，深色半透明；离开页面就停止。静态频谱使用 Spek 默认的 SoX 色阶（0 到 -120 dB），两者都在内存里算，不缓存、不落盘。
- 播放队列独立存在，可以随时打开、清空；清空会同时停止播放。
- 「刷新」重新扫描 `music/` 并核对数据库；「清空当前列表」只作用于定义这个列表的那一侧数据；「清除同步信息」保留本地文件，下次同步会自动重新关联。
- 设置里的缓存页可以逐项清理：封面、下载暂存、临时文件、musicdl 输出、自动获取的音源；「全部清除」不会动音乐库、数据库、凭证和配置。
- 设置里还可以把 `music/` 镜像到 U 盘，并生成一份相对路径的 `我喜欢的音乐.m3u8`。

## 第一次用

1. 到 Release 下载 `NeteaseVault-<版本号>-Setup.exe`，双击安装，选安装目录（默认是「当前目录\NeteaseVault」）。
2. 安装后整个目录可以搬走；删除目录就是卸载。升级只覆盖程序文件，`music/` 和 `data/` 里的个人数据会保留。
3. 打开程序，点左上角账户卡 → 「重新登录」，粘贴 Cookie（获取方法见下一节）。
4. 点「同步」，把「我喜欢的音乐」读进本地。
5. 切到「等待下载」，点「下载」；不选歌就是下载整个列表。
6. 下载完的文件在 `music/` 里，双击列表行就能播放。

## 账户与构建

当前版本 1.2.9。扫码登录已被网易关闭（服务端返回 8821），现在只有 Cookie：登录 music.163.com，F12 → Application → Cookies，复制 `MUSIC_U`。程序能解析整段请求头、分号列表和 JSON 三种粘贴形态，保存前会验证并显示昵称和 UID；凭证用 Windows DPAPI 加密，换个 Windows 账户读不出来。

从源码构建：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
pwsh -NoProfile -File build\build.ps1
```

构建会先生成 onedir 程序，跑一次 `--selftest`，再编译绿色安装器到 `release\NeteaseVault-<版本号>-Setup.exe`。安装器约 156 MB，由源码构建，不手工拼包。

装好后的目录只有三样：`NeteaseVault.exe`、`data/`、`music/`。`data/` 里同时放运行库、引擎、证书、数据库、凭证、配置、日志、缓存、暂存和自定义源脚本；`music/` 只放最终的歌。没有 `_internal`，不写注册表，不写 `%AppData%`。

## 边界

- 只支持 Windows 10/11。
- 只归档「我喜欢的音乐」一个歌单；不做云端上传，也不能编辑歌单。
- 不内置任何音源密钥或账号。自定义源要自己导入或自动获取，来源是公开第三方仓库，可用性不由程序保证，失效是常态。
- 假无损检测是启发式判断，不保证识别所有转码；灰区和无法判定都交给人。
- 网易的接口和风控随时可能变，同步或下载失效属于正常损耗，不是承诺。
